# infisical integration for kibamail ansible

this document explains how to use infisical for secret management with the kibamail ansible playbooks.

## prerequisites

1. install the infisical cli:
   ```bash
   # for debian/ubuntu
   curl -1sLf "https://dl.cloudsmith.io/public/infisical/infisical-cli/setup.deb.sh" | sudo -E bash
   sudo apt-get update && sudo apt-get install -y infisical

   # for macos
   brew install infisical/get-cli/infisical
   ```

2. obtain an infisical token:
   - log in to https://infisical.kibamail.com
   - create a service token with read access to your project
   - export the token as an environment variable:
     ```bash
     export INFISICAL_TOKEN=st.your-token-here
     ```

## fetching secrets from infisical

run the setup script to fetch secrets from infisical:

```bash
# for staging environment
./scripts/setup-infisical.sh staging

# for production environment
./scripts/setup-infisical.sh prod
```

this script will:
1. connect to infisical using the provided token
2. fetch the required secrets for the specified environment
3. store them in a `vault_secrets.txt` file
4. fail with a clear error message if any secrets cannot be fetched

the script includes robust error handling:
- it will show detailed error messages if secrets cannot be fetched
- it will exit with a non-zero status code if any secret fetch fails
- it will provide troubleshooting suggestions for common issues
- it will not allow playbooks to run with placeholder values

## vault_secrets.txt file

the `vault_secrets.txt` file contains the secrets fetched from infisical and is used when running ansible playbooks. this file should never be committed to git.

example content:
```
# ansible secrets for kibamail
# this file is automatically generated by setup-infisical.sh
# do not edit manually
# do not commit to git

# environment: staging
# generated on: Mon Jul 15 10:30:45 UTC 2024

MYSQL_ROOT_USER_PASSWORD=secure-password-123
MYSQL_KIBAMAIL_USER_PASSWORD=another-secure-password-456
```

## secret structure in infisical

organize your secrets in infisical with the following structure:

- environment: `staging` or `prod`
- secrets:
  - `ANSIBLE_MYSQL_ROOT_USER_PASSWORD`: root password for mysql
  - `ANSIBLE_MYSQL_KIBAMAIL_USER_PASSWORD`: kibamail application user password

## running playbooks

run playbooks using the provided script:

```bash
# for staging environment
./scripts/run-with-secrets.sh playbooks/mysql/setup.yml staging

# for production environment
./scripts/run-with-secrets.sh playbooks/mysql/setup.yml prod
```

## adding new secrets

to add new secrets:

1. add the secret to infisical with the appropriate name and environment
2. modify the `setup-infisical.sh` script to fetch the new secret:
   ```bash
   # add this line in the script
   fetch_secret "YOUR_SECRET_NAME" "YOUR_VARIABLE_NAME"
   ```
3. update the `run-with-secrets.sh` script to pass the new secret to ansible:
   ```bash
   # add this line in the ansible-playbook command
   -e "your_ansible_var=$YOUR_VARIABLE_NAME" \
   ```

## ci/cd integration

for github actions or other ci/cd systems:

1. store the infisical token as a repository secret
2. in your workflow, set up the environment and fetch secrets:
   ```yaml
   - name: fetch secrets from infisical
     env:
       INFISICAL_TOKEN: ${{ secrets.INFISICAL_TOKEN }}
     run: cd ansible && ./scripts/setup-infisical.sh staging
   ```

## testing environment

for testing in docker containers:

1. fetch secrets and create the vault_secrets.txt file:
   ```bash
   INFISICAL_TOKEN=your-token ./scripts/setup-infisical.sh staging
   ```

2. copy the vault_secrets.txt file into the ansible-root container:
   ```bash
   docker cp ansible/vault_secrets.txt ansible-root:/ansible/vault_secrets.txt
   ```

3. run ansible inside the container:
   ```bash
   docker exec ansible-root /bin/bash -c "cd /ansible && ./scripts/run-with-secrets.sh playbooks/mysql/setup.yml staging"
   ```

## troubleshooting

if you encounter python errors on macos related to `objc[72832]: +[__NSCFConstantString initialize]`, uncomment this line in your `vault_secrets.txt` file:

```
OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES
```

## security best practices

1. never commit the `vault_secrets.txt` file to version control
2. set restrictive permissions on the file: `chmod 600 vault_secrets.txt`
3. rotate infisical tokens regularly
4. use different tokens for different environments
5. limit token access to only the required secrets
6. audit secret access regularly through infisical logs
